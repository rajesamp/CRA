# Postmortem INC-1987: payment-gateway card-processor timeout lowered below peak latency

Service: payment-gateway. Change type: Config change. Severity: SEV2. Date: 2025-09-02.

## Summary

During a config cleanup, the connect timeout from payment-gateway to the
upstream card processor was lowered from 3000 ms to 800 ms to fail faster.
The processor's p99 latency during the evening peak is above 800 ms, so a
share of authorisations timed out and failed intermittently for about 50
minutes until the old value was restored.

## Root cause

The new timeout was chosen from average latency, not peak p99. The change was
reviewed as a cleanup with no behaviour change, so nobody compared it against
peak latency data.

## Action items

Compare any timeout change against peak p99 latency for the dependency it
guards. Treat timeout and retry values on the payment path as behaviour
changes, not cleanups.

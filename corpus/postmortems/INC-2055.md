# Postmortem INC-2055: payment-gateway HTTP client upgrade exhausted connections

Service: payment-gateway. Change type: Dependency upgrade. Severity: SEV1. Date: 2025-11-19.

## Summary

A major version upgrade of payment-gateway's HTTP client library reset the
default connection pool size from 100 to 10. At peak traffic, connections to
the card processor were exhausted, payment requests queued, and many timed out.
Checkout depended on these calls, so customers saw failed payments for about
35 minutes.

## Root cause

The upgrade changed a default the service relied on implicitly. The release
notes mentioned the new default, but the upgrade was reviewed as a routine
version bump and was not load tested.

## Action items

Pin connection pool sizes explicitly instead of relying on library defaults.
Load test dependency upgrades on the payment path before release. Read release
notes for changed defaults as part of upgrade review.
